# LangChain + LangGraph version of the RAG project

`rag_lc.py` rebuilds every variant (V1–V6) with LangChain and LangGraph. `rag_lib.py` is the hand-written original and is unchanged.
`run_lc.py` runs the LangChain version and writes `results_lc.json` in the same schema, so `judge.py`, `summarize.py` and `retrieval_eval.py` work on it.

## Where each concept lives in `rag_lc.py`

| LangChain / LangGraph idea | What it replaced | Where |
|---|---|---|
| `LLM` subclass (`ClaudeCLI`) | the `llm()` function | any model becomes a Runnable (`.invoke`, `.batch`, pipes) |
| `PromptTemplate` + `\|` (LCEL) | `str.format` + manual calls | `ANSWER`, `PLAN`, `CHECK`, `with_answer()` |
| `HuggingFaceEmbeddings`, `Chroma` | sentence-transformers + raw chromadb calls | `Stack.__init__` |
| `BM25Retriever` | 20 lines of hand-written BM25 (sparse matrix) | `_variants` |
| `EnsembleRetriever` (weighted RRF) | `rrf()` + `hybrid()` | `_variants` |
| `EmbeddingsRedundantFilter` | `uniq()` near-duplicate removal | `refine()` |
| `CrossEncoderReranker` + `ContextualCompressionRetriever` | `rerank()` | `refine()` |
| `BaseRetriever` subclass | routing and entity-graph logic | `RoutedDense`, `EntityGraphRetriever` |
| `RunnableParallel(...).assign(...)` | `answer()` | `with_answer()` returns `{question, docs, answer}` |
| LangGraph `StateGraph` | the `v6_agentic` function (plan, retrieve, check, maybe retrieve again, answer) | `Stack._agent` |
| callback handler (`BaseCallbackHandler`) | manual call counting and timing | `CallStats` |

Agentic graph (generated by `graph.get_graph().draw_mermaid()`): `plan -> check -> (follow_up) -> respond`, where the branch after `check` is
a conditional edge on whether the checker found missing facts.

## Did it reduce complexity?

**Lines of code** (non-blank, non-comment; features matched, i.e. leaving out what `rag_lib.py` has and `rag_lc.py` does not: tracing, replay, GPU lock, Qwen backend):

| Component | Hand-written | LangChain |
|---|---:|---:|
| Isolated `claude -p` call | 15 | 17 |
| Prompts + JSON parsing | 14 | 18 |
| Chunking + exact dedup | 20 | 17 |
| Embeddings, vector store, setup | 22 | 13 |
| Hierarchical routing | 15 | 24 |
| BM25 | 19 | 0 (one line) |
| Near-dup filter / rerank / fusion / hybrid | 36 | 9 |
| Entity graph (link, expand) | 60 | 36 |
| Variant wiring + answer chain | 39 | 17 |
| Agentic loop | 32 | 28 |
| **Total** | **272** | **179** |

The entity-graph row is not a fair win for LangChain: about 10 of the 60 hand-written lines build a `networkx` graph that retrieval never reads, and
the port simply leaves it out. Adjusting for that, the totals are 262 vs 179, about **32% fewer lines**.

**Where the savings are:** the plumbing LangChain already ships (BM25, rank fusion, near-duplicate filter, cross-encoder rerank, vector store,
answer chain). **Where there are none or it is worse:** the project-specific logic (entity graph barely shrinks), routing (longer, because a `BaseRetriever`
subclass needs boilerplate), prompts and the LLM wrapper (slightly longer), and the agentic loop (28 vs 32: LangGraph replaces `if`/sequential calls with
nodes and edges, which is clearer but not shorter).

**Cyclomatic complexity (radon):** average 4.0 (hand-written) vs 4.1 (LangChain), maximum function 13 vs 12. **No reduction.** The branching lives in the
domain logic (entity linking, graph expansion, chunking), and that did not move. Maintainability index is A for both (19 vs 31).

**Verdict:** LangChain cut the amount of code by about a third, almost all of it boilerplate, and did not make the hard parts simpler. The new pipeline is
more declarative and easier to recombine (swap a retriever, `.batch(...)` for parallel runs, callbacks, a graph diagram), but harder to see inside.

## What was lost or got worse

- **Transparency.** `rag_lib.py` records dense/BM25 ranks, cross-encoder scores and which chunk reached the LLM (the review CSVs come from that). LangChain's
  `CrossEncoderReranker` returns reordered documents without scores, so that trace is not reproduced (42 hand-written lines have no equivalent here).
- **Speed of retrieval.** Per query (retrieval only, CPU): baseline 6 ms vs 119 ms, rerank-8 37 vs 150 ms, hybrid 121 vs 347 ms, graph 88 vs 382 ms.
  `EmbeddingsRedundantFilter` re-embeds every candidate on every query, where the original reused stored embeddings. It is still tiny next to a 15–40 s LLM call.
- **Exact behaviour.** `BM25Retriever` (rank_bm25) and `EnsembleRetriever` are not identical to the hand-written BM25 and RRF: chunk overlap with the
  original is 94% (baseline), 88–89% (reranked), 71–72% (hybrid, graph).

## Do the results match?

Same 24 counterfactual questions, Haiku generator and judge (fact accuracy):

| Variant | Hand-written | LangChain | Difference (95% CI) |
|---|---:|---:|---|
| baseline | 58.6% | 59.9% | +1.4 [-1.7, +5.0] |
| rerank-3 | 57.9% | 57.0% | -0.8 [-2.5, 0.0] |
| rerank-8 | 70.7% | 74.5% | +3.7 [0.0, +9.6] |
| hierarchical | 57.9% | 57.9% | 0.0 |
| hybrid | 69.5% | 73.2% | +3.7 [-4.5, +12.5] |
| graph | 86.7% | 84.6% | -2.1 [-6.7, +2.0] |
| agentic | 98.6% | 89.9% | **-8.8 [-17.1, -1.9]** |

Ranking and conclusions are the same except for agentic. Its drop is statistically real. Replaying the original run's sub-queries through the LangChain
retriever gives context recall 95.6% vs 98.6%, so a small part is the retrieval difference (BM25/fusion). The rest is the planner and checker writing
different queries on the new run; I did not repeat either run, so how much is chance is unknown.
Retrieval-only metrics for the port are in `review/retrieval_metrics_lc.md` (graph still best: MRR 0.95, nDCG@8 54%).

## Gotchas hit while porting (useful to know)

1. `langchain_community.vectorstores.Chroma` is deprecated; use `langchain_chroma.Chroma`. Several classes now live in `langchain_classic`.
2. Chroma search results come back as `Document`s with `id=None`; key chunks by their text (`pos` dict) instead.
3. `EmbeddingsRedundantFilter` leaves private state on its output documents; feeding them to a second filter crashes with `KeyError: 'embedded_doc'`.
   Rebuild fresh `Document`s between stages (done in `EntityGraphRetriever`).
4. `add_conditional_edges` needs a path map, otherwise the graph still runs but its diagram and static checks show no branches.

## Reproduce

```
python run_lc.py --out results_lc.json            # generation (Haiku)
python judge.py results_lc.json                   # semantic judge
python summarize.py results_lc.json               # ranking
python retrieval_eval.py results_lc.json review/retrieval_metrics_lc.md
radon raw rag_lib.py rag_lc.py; radon cc rag_lib.py rag_lc.py -s -a
```
